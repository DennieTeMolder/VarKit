This vignette will showcase all of the basic functionality found in the varkit package.

Setup

We start off by loading the package and defining the path to the VCF file we wish to load. The file can be either compressed or uncompressed, but for this example we will use a block-gzipped VCF:

library(varkit)

# This might need to be increased for large VCFs
Sys.setenv("VROOM_CONNECTION_SIZE" = 1e6)

path <- system.file("extdata", "celegans.vcf.bgz", package = "varkit")

NOTE: if you want to use tidyverse or more specifically stringr, it is recommended to load that library first. Due to the collision with the fixed() function.

Loading a VCF into R

In it’s simplest form you would load a VCF file into memory like so:

vcf <- read_vcf(path, ploidy = 2)

However, it is good practice to first validate if the VCF header is parsed correctly:

The most important information here is the column names, which are printed last (located under header$col_names). If the VCF file is recognised correctly it should list all of the fixed fields and samples present in your VCF. Masking

A common operation when working with VCF is removing specific sites, based on various criteria. In VarKit this is achieved through the mask() function, which either requires you to input a logical vector (TRUE if the site should be masked) or a data frame with columns “chorm” and “pos” containing the sites to be masked. For this example we will use a logical vector to mask/hide all sites on chromosome I:

# This is a logical vector
mask_site <- fixed(vcf)$chrom == "I"

# Be sure to reassign the returned object to `vcf` otherwise the mask will not take effect
vcf <- mask(vcf, site = mask_site)

# Use the summary function to check the number of visible sites
summary(vcf)
#> # A tibble: 1 × 4
#>   samples sites_visible sites_total visible_frac
#>     <int>         <int>       <int>        <dbl>
#> 1      15           201         285        0.705

Now if we fetch data from the VCF object the masked sites will no longer be returned. For example if we retrieve the fixed fields we can see that the sites with CHROM = “I” are missing (if you look back, you can see that they were previously on top):

It is important to note that masking can be performed multiple times in sequence, which will cause sites in either mask to be excluded:

# Let's use a data frame this time around
sites_to_mask <- dplyr::filter(fixed(vcf), qual < 3000)
nrow(sites_to_mask)
#> [1] 3
vcf <- mask(vcf, site = sites_to_mask)
summary(vcf)
#> # A tibble: 1 × 4
#>   samples sites_visible sites_total visible_frac
#>     <int>         <int>       <int>        <dbl>
#> 1      15           198         285        0.695

You can see that this filter masked an additional 3 sites.

Masking sites without variation

A common task after subsetting or converting VCF files is removing/masking sites that no longer contain variation. VarKit provides a convenient function to achieve this:

vcf <- mask_sites_without_variation(vcf)
summary(vcf)
#> # A tibble: 1 × 4
#>   samples sites_visible sites_total visible_frac
#>     <int>         <int>       <int>        <dbl>
#> 1      15           197         285        0.691

If you compare with the previous summary() you can see that 1 additional site was masked because it lacked variation.

Using multiple masks

This process is called ‘masking’ not ‘removing’ sites, because the sites are not actually removed from memory, they are just skipped by the VarKit functions. This allows you to quickly unmask sites or restore an exported set of masked sites.

In this example we will fist export the mask we just created (which masks sites on CHROM = “I” or sites with a QUAL < 3000) and assign it to the my_mask variable, then we will remove the mask from the vcf object which verify through the summary() function:

my_mask <- export_mask(vcf)
vcf <- unmask_all(vcf)
summary(vcf)
#> # A tibble: 1 × 4
#>   samples sites_visible sites_total visible_frac
#>     <int>         <int>       <int>        <dbl>
#> 1      15           285         285            1

Then if we later decide that we need the mask again, we can import it:

vcf <- import_mask(vcf, my_mask)
summary(vcf)
#> # A tibble: 1 × 4
#>   samples sites_visible sites_total visible_frac
#>     <int>         <int>       <int>        <dbl>
#> 1      15           197         285        0.691

In this way you could use different masks for different parts of your analysis/script.

Removing sites

In some cases, e.g. when you need to free memory or when you need maximum lookup speed, it is possible to entirely remove sites (meaning they cannot be retrieved by unmasking):

reduced_vcf <- remove_masked(vcf)
summary(reduced_vcf)
#> # A tibble: 1 × 4
#>   samples sites_visible sites_total visible_frac
#>     <int>         <int>       <int>        <dbl>
#> 1      15           197         197            1

Writing VCF files

Varkit also has the ability to write VCF files. This is useful for example when you have removed specific sites or samples and want to write the reduced file.

Moreover, masks are also stored in the FILTER column of the resulting VCF file if replace_filter = TRUE, allowing you to save and load a masked VCF:

temp_file <- tempfile(fileext = ".vcf.bz2")
write_vcf(vcf, path = temp_file, replace_filter = TRUE)
#> Creating missing columns: filter, info
#> Representing missing genotypes as: './.'

Detecting linkage between sites

Lastly, the VarKit package provides functions to detect linkage between sites. These functions use the stats::cor(..., method = "pearson", use = "pairwise.complete.obs") internally, thus you can lookup its documentation for more information.

In order for this to work geno(vcf) should contain only numeric values (or NA). Most likely you genotype fields will be in the string format and thus need to be converted. How to achieve this is highly circumstantial and will require manual parsing/conversion. For tips take a look at the “Notes for advanced users” section at the bottom.

As you might have noticed, the example file contains genotype calls (GT, e.g. “0/1”), which will first convert to numeric dosages using a hidden function:

# The function below is not exported as it is not very robust, use it with caution!
vcf$geno <- varkit:::.bi_gt2dosage(vcf$geno)

Although you could use the find_linked_sites() function directly, on larger VCF files you can speed up the process by first checking for identical columns (i.e. R2 = 1):

llist <- find_identical_sites(vcf, cores = 1)
summary(llist)
#> # A tibble: 1 × 6
#>   n_total n_node n_unlinked n_keep n_remove frac_remove
#>     <int>  <int>      <int>  <int>    <int>       <dbl>
#> 1     197     18         37     55      142       0.721

This will return a “link_list” object that tracks which sites (using their index) are linked to each other and contains information on which sites to mask in order to remove linkage (see also varkit_help(llist)). Therefore, we can use this object to mask sites in order to remove the linkage (this will mask all but the centre most site out of sets of identical/linked sites):

vcf <- mask(vcf, site = llist)
summary(vcf)
#> # A tibble: 1 × 4
#>   samples sites_visible sites_total visible_frac
#>     <int>         <int>       <int>        <dbl>
#> 1      15            55         285        0.193

Now that identical sites are masked we can check for linkage on the reduced set of sites. Here we will use an cutoff of R2 = 0.7:

llist <- find_linked_sites(vcf, cutoff = 0.7, window = 5e4, cores = 1)
vcf <- mask(vcf, site = llist)
summary(vcf)
#> # A tibble: 1 × 4
#>   samples sites_visible sites_total visible_frac
#>     <int>         <int>       <int>        <dbl>
#> 1      15            44         285        0.154

It is important to know that find_indentical_sites() checks entire chromosomes/scaffolds, whereas find_linked_sites() only checks for linkage within a specified window (here we use the default of 50,000 bp). To check entire chromosomes in the latter case set the “window” option to 0 or -1.

Both of these function support multi-threading through the “cores” option and only look for identical/linked columns within chromosomes/scaffolds. To check for linkage between all chromosomes set by_chrom = FALSE. However, this will greatly increase computational load.

Reading/writing link_list objects to file

It might be interesting to store the information about linked sites as it will tell you the extend of linkage and which sites are a “proxy” of others:

temp_file <- tempfile(fileext = ".json")
write_link_list(llist, path = temp_file)

Which can then be read back into memory like so:

llist2 <- read_link_list(temp_file)
summary(llist2)
#> # A tibble: 1 × 6
#>   n_total n_node n_unlinked n_keep n_remove frac_remove
#>     <int>  <int>      <int>  <int>    <int>       <dbl>
#> 1      55      2         42     44       11         0.2

Notes for advanced users

Modifying the varkit object directly

It is safe to directly modify the varkit object using the $ operator as long as nrow(vcf$fixed) == ncol(vcf$geno) == length(vcf$use_sites), the vcf$fixed$chrom & vcf$fixed$pos columns are retained, and vcf$geno keeps the ‘varkit_geno’ class (the latter may be violated when extracting, e.g. geno(vcf)[, 1], which will remove the class).

The attentive reader might have noticed that we have already made use of this before:

vcf$geno <- varkit:::.bi_gt2dosage(vcf$geno)

To retain the “varkit_geno” class use the varkit_geno() function, e.g.:

vcf$geno <- varkit_geno(my_matrix) # this is an example, my_matrix is not defined here

Or use one of the the provided apply wrappers:

# Here `x` contains all genotypes for a single site (length == # samples)
vcf$geno <- apply_sites(vcf$geno, function(x) x + 1)

# Here `x` contains all genotypes for a sample (length == # sites)
vcf$geno <- apply_samples(vcf$geno, function(x) x - 1)

Above we do not use geno(vcf) as that function only returns the non-masked sites.

NOTE: the apply wrappers will only retain the “varkit_geno” class if the function returns a vector of the same length as the input.

A closer look into the link_list object

Link_list objects are lists that contain a 0 if the site at the matching index is not linked to any other site. If it contains any other number (or multiple numbers) the site at that index is linked to sites at the index of the listed numbers and this site is to be retained when removing linkage. If it contains NA the site is linked to at least one other sited and this site should be excluded to remove the linkage.

Armed with this knowledge let’s take a look at the link_list we generated previously:

print(llist, n = 10)
#> *A link_list object*
#> [[1]]: 7
#> [[2]]: NA
#> [[3]]: 0
#> [[4]]: 0
#> [[5]]: 0
#> [[6]]: 0
#> [[7]]: NA
#> [[8]]: NA
#> [[9]]: 0
#> [[10]]: 2, 12, 39, 8, 11, 21, 24, 29, 30, 13
#>  ...
#> # Total length: 55 
#> 
#> With a integer translation layer:
#>  89, 92, 93, 94, 98, 102, 108, 111, 112, 113 ...

Here you can see that the 1st site in the masked vcf (which is actually site 1024 in the original vcf, according to the translation layer) is linked to the 8th site in the masked vcf. In order to remove this link, the mask(vcf, llist) function will mask the 8th site and keep the 1st. Moving on, the 2nd site is linked to some other site (if we look further down we can see it is linked to the 9th site) and the mask() function will mask this site in order to remove this link. Finally, the 3rd site in the masked vcf is not linked to any other site and thus will not be masked when using the mask() function.
