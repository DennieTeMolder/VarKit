This vignette will showcase all of the basic functionality found in the varkit package.

Setup

We start off by loading the package and defining the path to the VCF file we wish to load. The file can be either compressed or uncompressed, but for this example we will use a block-gzipped VCF:

library(varkit)

file <- system.file("extdata", "celegans.vcf.bgz", package = "varkit")

Loading a VCF into R

In it’s simplest form you would load a VCF file into memory like so:

vcf <- read_vcf(file)

However, it is good practice to first validate if the VCF header is parsed correctly:

header <- read_vcf_header(file)
print(header)

The most important information here is the column names, which are printed last (located under header$col_names). If the VCF file is recognised correctly it should list all of the fixed fields and samples present in your VCF. The column names listed in the header can be provided to the read_vcf() function in order to exclude them. This is useful if you want to exclude specific samples, or if you know you are not going to use certain fixed fields and want to save memory.

For example here we exclude the “INFO” and “FILTER” fixed fields and the sample “N2”:

vcf <- read_vcf(file, col_select = c(-info, -filter, -N2))

Masking

A common operation when working with VCF is removing specific sites, based on various criteria. In VarKit this is achieved through the mask() function, which either requires you to input a logical vector (TRUE if the site should be masked) or a data frame with columns “chorm” and “pos” containing the sites to be masked. For this example we will use a logical vector to mask/hide all sites on chromosome I:

# This is a logical vector
mask_site <- site(vcf)$chrom == "I"

# Be sure to reassign the returned object to `vcf` otherwise the mask will not take effect
vcf <- mask(vcf, site = mask_site)

# Use the summary function to check the number of visible sites
summary(vcf)
#> # A tibble: 1 × 4
#>   samples sites_visible sites_total visible_frac
#>     <int>         <int>       <int>        <dbl>
#> 1      15            40          60        0.667

Now if we fetch data from the VCF object the masked sites will no longer be returned. For example if we retrieve the site information (fixed fields) we can see that the sites with CHROM = “I” are missing (if you look back, you can see that they were previously on top):

It is important to note that masking can be performed multiple times in sequence, which will cause sites in either mask to be excluded:

# Let's use a data frame this time around
sites_to_mask <- dplyr::filter(site(vcf), qual < 3000)
nrow(sites_to_mask)
#> [1] 2
vcf <- mask(vcf, site = sites_to_mask)
summary(vcf)
#> # A tibble: 1 × 4
#>   samples sites_visible sites_total visible_frac
#>     <int>         <int>       <int>        <dbl>
#> 1      15            38          60        0.633

You can see that this filter masked an additional 3 sites.

Masking sites without variation

A common task after subsetting or converting VCF files is removing/masking sites that no longer contain variation. VarKit provides a convenient function to achieve this:

vcf <- mask_sites_without_variation(vcf)
summary(vcf)
#> # A tibble: 1 × 4
#>   samples sites_visible sites_total visible_frac
#>     <int>         <int>       <int>        <dbl>
#> 1      15            38          60        0.633

If you compare with the previous summary() you can see that 1 additional site was masked because it lacked variation.

Using multiple masks

This process is called ‘masking’ not ‘removing’ sites, because the sites are not actually removed from memory, they are just skipped by the VarKit functions. This allows you to quickly unmask sites or restore an exported set of masked sites.

In this example we will fist export the mask we just created (which masks sites on CHROM = “I” or sites with a QUAL < 3000) and assign it to the my_mask variable, then we will remove the mask from the vcf object which verify through the summary() function:

my_mask <- export_mask(vcf)
vcf <- unmask_all(vcf)
summary(vcf)
#> # A tibble: 1 × 4
#>   samples sites_visible sites_total visible_frac
#>     <int>         <int>       <int>        <dbl>
#> 1      15            60          60            1

Then if we later decide that we need the mask again, we can import it:

vcf <- import_mask(vcf, my_mask)
summary(vcf)
#> # A tibble: 1 × 4
#>   samples sites_visible sites_total visible_frac
#>     <int>         <int>       <int>        <dbl>
#> 1      15            38          60        0.633

In this way you could use different masks for different parts of your analysis/script.

Removing sites

In some cases, e.g. when you need to free memory or when you need maximum lookup speed, it is possible to entirely remove sites (meaning they cannot be retrieved by unmasking):

reduced_vcf <- delete_masked_sites(vcf)
summary(reduced_vcf)
#> # A tibble: 1 × 4
#>   samples sites_visible sites_total visible_frac
#>     <int>         <int>       <int>        <dbl>
#> 1      15            38          38            1

Writing VCF files

Varkit also has the ability to write VCF files. This is useful for example when you have removed specific sites or samples and want to write the reduced file.

Moreover, masks are also stored in the FILTER column of the resulting VCF file if replace_filter = TRUE, allowing you to save and load a masked VCF:

temp_file <- tempfile(fileext = ".vcf")
write_vcf(vcf, file = temp_file, replace_filter = TRUE)

Detecting linkage between sites

Lastly, the VarKit package provides functionality to detect and remove linkage between sites. Internally this package reimplements stats::cor(..., method = "pearson", use = "pairwise.complete.obs") to utilize BLAS, thus using a faster BLAS library like openBLAS should improve performance.

In order for this to work geno(vcf) should contain only numeric values (or NA). Most likely your genotype fields will be in the string format and thus need to be converted. How to achieve this is highly circumstantial and will require manual parsing/conversion. For tips take a look at the “Notes for advanced users” section at the bottom.

As you might have noticed, the example file contains complex genotypes that consist of multiple parts (delimited by a colon) that are described in the ‘format’ column of site(vcf). We first extract the genotype calls (GT, e.g. “0/1”) from these complex fields, which we then convert to numeric dosages using a hidden function:

# Overwriting geno(vcf) is only allowed when it has no masked sites
vcf <- unmask_all(vcf)
geno(vcf) <- parse_geno(vcf, type = "GT")
# The function below is not exported as it is not very robust, use it with caution!
geno(vcf) <- varkit:::.bi_gt2dosage(geno(vcf))

Now we run find_linked_sites() to obtain a list of dataframes with sites that have an R2 above the specified cutoff for each CHROM. Then we call resolve_links() to determine which sites should be excluded if we want to remove as many of the detected links as possible (very few links could remain).

links <- find_linked_sites(vcf, cutoff = 0.9, size_bp = 1e5, windows = 2, by_chrom = TRUE, cores = 1)
#> ℹ Running 5 comparisons between 4 windows
#> ℹ Collecting results
#> ✔ Collecting results [5ms]
#> 
lgraph <- resolve_links(links, cores = 1)

Here we use a sliding window spanning 2 (n_window) X 1e5 base pairs (window_bp_size) = 2e5 bases to the left AND right (effectively 4e5 bases) of any given site. You could use any combination of n_window and window_size_bp to achieve this number, but there is a trade-off in computational efficientcy that you should try to balance. Generally one should first increase window_size_bp to 1e5 and then achieve a higher size by increasing n_window above 1. The n_window argument can also be set to a negative number, in which case all sites within each CHROM are compared (the window size will still impact performance). To enable comparisons between chromosomes set by_chrom to FALSE (when n_window > 0 only chromosomes that follow one another in the VCF are compared).

summary(lgraph, vcf = vcf)
#> # A tibble: 1 × 5
#>   n_remove n_proxy n_singletons n_total frac_remove
#>      <int>   <int>        <dbl>   <int>       <dbl>
#> 1       35      13            0      60       0.583

This will return a directed acyclic graph in which each node is labeled with the (column) index of a site in the unmasked vcf. Each node that should be removed to reduce linkage is connected to a note that will be retained and is guaranteed to have an R2 above the cutoff (retained -> removed). Please refer to the Igraph package for information on working with these graphs.

Luckily there is no need to understand graph theory as the removal of linked sites can be automated by passing the graph as the second argument to the mask() function. In the resulting vcf, for each group of linked sites, the single best site is retained and all others are masked, thus representing the most amount of information with the least amount of variants.

vcf <- mask(vcf, site = lgraph)
summary(vcf)
#> # A tibble: 1 × 4
#>   samples sites_visible sites_total visible_frac
#>     <int>         <int>       <int>        <dbl>
#> 1      15            25          60        0.417

Notes for advanced users

Modifying the varkit object directly

It is safe to directly modify the varkit object using the $ operator as long as nrow(vcf$site) == ncol(vcf$geno) == length(vcf$use_sites), the vcf$site$chrom & vcf$site$pos columns are retained, and vcf$geno keeps the ‘varkit_geno’. However it is generally advised to use the setter functions to modify varkit objects (e.g. geno(vcf) <- my_new_value).

A condensed version of the example given before:

geno(vcf) <- parse_geno(unmaks_all(vcf), type = "GT")

This is how you would modify the object directly (using one of the handy apply wrappers):

# Here `x` contains all genotypes for a single site (length == # samples)
vcf$geno <- apply_sites(vcf$geno, function(x) x + 1)

# Here `x` contains all genotypes for a sample (length == # sites)
vcf$geno <- apply_samples(vcf$geno, function(x) x - 1)

Be warned that, in the above example, you will responsible for ensuring that the previously mentioned constraints are satisfied! Also note that we do not use geno(vcf) as that function only returns the non-masked sites.

NOTE: the apply wrappers will only retain the “varkit_geno” class if the function returns a vector of the same length as the input.
